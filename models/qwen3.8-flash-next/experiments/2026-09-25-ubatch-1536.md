## Hypothesis

Prefill is bound by per-ubatch host synchronisation in the MoE layers (144 host syncs per ubatch), so fewer, larger ubatches should read prompts faster. `-ub 2048` does not fit with MTP at 262K, but at `-ub 1024` the fullest card peaked at 27.8 GiB of its 32 GB. A 1.5x larger ubatch should fit if the first card gives up a layer; it also holds the vision projector. Expected: a few percent on prefill, no change in decode.

## Change

```diff
- -ub 1024 -ts 13,13,13,10
+ -ub 1536 -ts 12,13,13,11
```

## Procedure

Restart with the change and run [`tools/fnbench.py`](../../../tools/fnbench.py) including `LONG_TOKENS=200000` (a 219,217-token prompt), logging per-card VRAM and driver-held host RAM throughout.

## Correctness

Not applicable beyond the sanity question (answered correctly): only the ubatch size changed.

## Decision

Kept. Prefill is 4.5-6% faster at depth for 0.4 GiB more VRAM on the fullest card and 6 GiB more driver-held host RAM, which the 128 GB host can afford. It has been the default since 2026-09-25.
